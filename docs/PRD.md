## 1. 背景与愿景

### 1.1 一句话

**Synapse Nexus 是一款面向开发者与知识工作者的中英文混说语音输入法，让"想到 → 说出 → 落到光标处"在 1.5 秒内完成。**

### 1.2 为什么现在做（Why now）

- 流式 ASR 大模型 API（豆包、Paraformer、SenseVoice）首字延迟已经做到 ≤ 800ms，**第一次让"语音输入"在工程上不再是延迟妥协的产物**。
- 通用大模型（Qwen-Flash 量级）做后处理（Polish）成本已经 ≤ 0.001 元/千字，**第一次让"上下文修正"在商业上闭得了环**。
- Linux 桌面（Ubuntu / Fedora / Arch）至今**没有**一个真正能用的中英混说语音输入法 —— Rime/Fcitx5 + 系统 ASR 全都缺少"领域 Polish"那一层。
- 开发者群体写代码、写文档、写 commit message 的语料天然中英混合，是被传统输入法系统性忽视的人群。

### 1.3 产品名释义

- **Synapse**（突触）：指人脑神经元之间的信号传递，象征"思想 → 文字"的低延迟连接。
- **Nexus**（节点 / 联结）：指中文、英文、领域术语三者在一个输入流中的汇合。
- 中文产品名暂定 **"言枢"**（待品牌定）。

## 2. 目标与非目标

### 2.1 目标（v1.0 GA 时必须达成）

| ID | 目标 | 衡量方式 |
|---|---|---|
| G-1 | Ubuntu 上可用、稳定、可日常使用的语音输入法 | 在 fcitx5 上连续运行 8 小时无崩溃；首字延迟 P95 ≤ 1.5s |
| G-2 | 中英文混说零切换 | 用户**不需要**手动切换语言，"打开 Cursor 写一个 fetch 请求"能一次出对 |
| G-3 | 领域术语 Polish 命中 | 编程 / AI / 金融三个 demo 词库下，命中率 ≥ 90% |
| G-4 | 商业闭环跑通 | 按量付费 + 余额预警 + 充值上线，至少 50 个付费用户 |

### 2.2 非目标（v1.0 不做）

- ❌ **离线纯本地识别**（仅做"网络故障兜底"，不追求全离线精度）
- ❌ **方言识别**（粤、川、闽南话等长尾语种）
- ❌ **自研 ASR / LLM 模型**
- ❌ **拼音 / 笔画 / 五笔输入**（这是语音输入法，不是综合输入法）
- ❌ **iOS / Windows 在 v1.0 阶段达到 GA**（见 §8 平台策略）

### 2.3 反目标（**永久拒绝，需创始人重新评审才能解除**）

> 以下三项已在 2026-05-31 锁定为永久反目标，不进入任何后续版本的需求池。

- 🔒 **订阅制定价**（重度用户会薅羊毛、轻度用户感觉亏；按量付费 + 阶梯包是唯一定价方向）
- 🔒 **离线纯本地识别**（v1.x / v2.x 都不做，本地只做"网络故障兜底"）
- 🔒 **方言识别**（粤、川、闽南话等长尾语种永不在路线图上）

其它反目标（不强约束，可在版本评审中重议）：

- ❌ **强绑定登录才能用**（首次启动给 1000 字免费额度，无需登录）
- ❌ **任何形式的"用户语音上云训练"**（合规高压线，写进首次启动协议）

## 3. 目标用户与画像

### 3.1 主画像 P-1：Linux 重度开发者（North Star）

- 用 Ubuntu / Fedora / Arch 作为日常开发机
- 每天需要写：代码注释、commit message、技术文档、Slack/飞书消息、邮件
- 痛点：当前要么用拼音慢、要么用讯飞但中英切换烦
- 付费意愿：**高**（已经在为 Cursor / GitHub Copilot / ChatGPT 付费）
- 估算规模：中国大陆 50 万 ~ 100 万

### 3.2 次画像 P-2：知识工作者（产品经理 / 研究员 / 创业者）

- 主要用 macOS / Windows，但有 WSL / 远程 Ubuntu 的开发环境
- 写作量大，对术语 Polish 敏感
- v1.x 阶段服务（Windows TSF 上线后）

### 3.3 反画像

- 不是给老人 / 学生群体的语音输入
- 不是给视障用户的辅助工具（虽然欢迎，但不为此做特殊设计）
- 不是给短视频创作者做字幕的（那是 ASR 工具，不是输入法）

## 4. 用户故事与关键场景

### 4.1 核心 user stories

```
US-01 (P0)
作为 Ubuntu 上的开发者，
我希望按住 Super+Space 说话、松开后文字直接出现在光标处，
以便我能用语音写完一个 commit message 而不用切窗口。

US-02 (P0)
作为中英文混说的用户，
我希望说"用 fetch API 拿一下 user list"时输出就是
"用 fetch API 拿一下 user list"，
而不是"用 fetch a p i 拿一下 user 列 表"或者"用 face api..."。

US-03 (P0)
作为对成本敏感的用户，
我希望知道我说了多少字、还剩多少额度、什么时候会扣费，
以便我能决定是不是该续充。

US-04 (P1)
作为说话有口头禅的用户（"嗯"、"那个"、"就是"），
我希望系统自动过滤掉这些口水词，
以便我说出来的就是能直接发出去的文字。

US-05 (P1)
作为有专业领域的用户（如 AI / 法律 / 医疗），
我希望系统逐渐学到我常用的术语（如把"Rest"识别成"Rust"），
以便用得越久越准。

US-06 (P2)
作为多设备用户，
我希望我的热词库 / 修正历史在 Ubuntu / Windows / iOS 间同步，
以便换设备不用重新教。
```

### 4.2 关键场景脚本

**场景 A：写 commit message（P-1 高频，每天 10+ 次）**

```
1. 用户在 terminal 里 `git commit`
2. 编辑器（vim / nano / VSCode）打开
3. 用户按住 Super+Space
4. 说："修了一下登录页 token 刷新的 bug，顺便把 retry 改成指数退避"
5. 松开
6. 期望输出（≤ 1.5s 内开始流式打字）：
   "修了一下登录页 token 刷新的 bug，顺便把 retry 改成指数退避"
```

**场景 B：飞书 / Slack 群里回消息**

```
1. 用户聚焦输入框
2. 按住 Super+Space
3. 说："我看了下你那个 PR，feedback 我加在 line 42 那个 useEffect 里了"
4. 松开
5. 期望输出：
   "我看了下你那个 PR，feedback 我加在 line 42 那个 useEffect 里了"
```

**场景 C：网络抖动**

```
1. 用户在地铁上
2. 按住快捷键说话
3. 当前 ASR 请求失败（网络丢包）
4. 期望行为：
   - 不要崩溃，不要弹错误对话框
   - 触发本地兜底（sherpa-onnx 小模型），输出"快速识别"标签
   - 状态栏显示一个不显眼的"离线模式"图标
   - 不计费
```

## 5. 功能需求（FR）

> 编号规则：FR-{模块}-{序号}。P0 = MVP 必做，P1 = v1.0 必做，P2 = v1.x。

### 5.1 输入触发与控制（FR-INPUT）

| ID | 优先级 | 描述 |
|---|---|---|
| FR-INPUT-01 | P0 | 支持"按住说话"模式（push-to-talk），默认快捷键 `Super+Space` |
| FR-INPUT-02 | P0 | 支持"切换式"模式（按一次开始，再按一次停止） |
| FR-INPUT-03 | P0 | 录音时显示一个不抢焦点的浮动指示器（音量条 + 状态文字） |
| FR-INPUT-04 | P1 | 快捷键可在设置中自定义 |
| FR-INPUT-05 | P1 | VAD（静音 1.2s 自动停止） |

### 5.2 识别核心（FR-ASR）

| ID | 优先级 | 描述 |
|---|---|---|
| FR-ASR-01 | P0 | 接入豆包流式 ASR（WebSocket），首字延迟 P95 ≤ 1.5s |
| FR-ASR-02 | P0 | 中英文自动混合识别，无需用户切换 |
| FR-ASR-03 | P0 | 流式增量渲染：识别中的文字以"灰色草稿态"显示在目标输入框，最终态变黑 |
| FR-ASR-04 | P1 | 本地兜底：sherpa-onnx + 一个小型中文模型，仅在云端失败时启用 |
| FR-ASR-05 | P1 | Provider 抽象：可在设置中切换 ASR 提供方（豆包 / Paraformer / 用户自填 OpenAI 兼容端点） |

### 5.3 Polish 后处理（FR-POLISH）

| ID | 优先级 | 描述 |
|---|---|---|
| FR-POLISH-01 | P0 | 调用 Qwen-Flash 类 LLM，输入"原始 ASR 结果 + 上下文 50 字 + 用户词库 + 系统词库"，输出修正后文本 |
| FR-POLISH-02 | P0 | Polish 必须在 ≤ 600ms 内返回，否则**直接放弃**用原始结果，不能阻塞输出 |
| FR-POLISH-03 | P0 | 内置三个领域词库：`code`（编程）、`ai`（AI/ML）、`general`（通用），用户可启用/禁用 |
| FR-POLISH-04 | P1 | 用户自定义词库：UI 增删改 |
| FR-POLISH-05 | P1 | 动态学习：分析最近 50 次"用户手动改写"的差异，自动生成修正规则进入私有 prompt |

### 5.4 上下文与词库（FR-CTX）

| ID | 优先级 | 描述 |
|---|---|---|
| FR-CTX-01 | P0 | 抓取光标前 50 字作为 Polish 上下文 |
| FR-CTX-02 | P1 | 识别当前应用并应用对应词库（如 VSCode → 启用 `code` 词库） |
| FR-CTX-03 | P2 | 跨设备同步用户词库（端到端加密） |

### 5.5 计费与额度（FR-BILL）

| ID | 优先级 | 描述 |
|---|---|---|
| FR-BILL-01 | P0 | 按"最终输出字数"计费（不按音频时长），单价待定（参考成本 × 3） |
| FR-BILL-02 | P0 | 首次启动赠送 1000 字免费额度，无需登录 |
| FR-BILL-03 | P0 | 状态栏实时显示剩余额度 |
| FR-BILL-04 | P0 | 余额 ≤ 100 字时弹出非阻塞提醒 |
| FR-BILL-05 | P1 | 阶梯定价：充得越多单价越低（如 10 元 / 50 元 / 200 元 三档） |
| FR-BILL-06 | P1 | 余额耗尽时自动降级到本地兜底，并标注"免费模式" |

### 5.6 隐私与设置（FR-PRIV）

| ID | 优先级 | 描述 |
|---|---|---|
| FR-PRIV-01 | P0 | 默认**不**保留任何音频文件，识别结束立刻删除 |
| FR-PRIV-02 | P0 | 默认**不**上传识别文本用于训练 |
| FR-PRIV-03 | P0 | 设置中可手动开启"本地保留 7 天历史"用于调试 |
| FR-PRIV-04 | P0 | 在金融、医疗类应用（按 bundle id / window class 识别）默认走本地兜底，不上云 |

## 6. 非功能需求（NFR）

| 维度 | 指标 | 验证方式 |
|---|---|---|
| **首字延迟** | P50 ≤ 800ms / P95 ≤ 1.5s（按下快捷键 → 第一个字出现在光标） | 内置埋点 |
| **整句延迟** | 5 秒语音的 P95 ≤ 4s（含 Polish） | 内置埋点 |
| **识别准确率** | 通用语料 CER ≤ 6%，中英混说 CER ≤ 10% | 自建 200 条评测集，每周回归 |
| **Polish 命中率** | 三个领域词库下 ≥ 90% | 同上 |
| **可用性** | 月度可用性 ≥ 99.5%（不含云端 ASR 提供方故障） | 客户端心跳 + 本地兜底兜住 |
| **崩溃率** | daemon 崩溃 < 0.1% sessions | 自动 crash report（用户同意后） |
| **资源占用** | 待机内存 ≤ 80MB，识别峰值 ≤ 200MB；CPU 待机 ≤ 1% | `top` / `htop` |
| **冷启动** | daemon 启动到 ready ≤ 1.5s | systemd unit 计时 |
| **安装包** | Ubuntu .deb ≤ 30MB（不含可选本地模型） | CI 输出 |
| **隐私** | 默认零音频持久化、零文本上云训练 | 代码审计 + 文档承诺 |

## 7. 成功指标（North Star）

### 7.1 北极星指标

**WAU 中"用语音输入了 ≥ 500 字"的用户数**

理由：用户量大但都只用 50 字试一下没意义；这个指标同时反映**用户拉新 × 留存 × 真实使用深度**。

### 7.2 关键支撑指标

| 漏斗 | 指标 | v1.0 目标（上线 3 个月） |
|---|---|---|
| 拉新 | 月安装量 | ≥ 5,000 |
| 激活 | 安装后 7 天内说过 ≥ 100 字 | ≥ 40% |
| 留存 | W4 留存（第 4 周还在用） | ≥ 25% |
| 付费 | 安装→付费转化 | ≥ 3% |
| 满意度 | NPS | ≥ 30 |
| 工程 | 首字延迟 P95 | ≤ 1.5s |

## 8. 平台策略

| 平台 | 阶段 | 入口技术 | 决策理由 |
|---|---|---|---|
| **Ubuntu (X11 + Wayland)** | **v1.0 GA**（先做） | Fcitx5 engine（C++）调用 Rust core daemon | 空白市场、目标用户高重叠、IME 框架最干净 |
| **Windows 10/11** | v1.1 | TSF Text Service（C++）调用同一 Rust core daemon | 用户群最大；TSF 已成熟但开发量大 |
| **iOS 16+** | v1.2 | Keyboard Extension（Swift）+ Rust core 编译为静态库 | 沙盒和审核风险最高；放最后 |
| **macOS** | v2.0 | InputMethodKit | 与 iOS 共享 80% 代码 |
| **Android** | 暂不做 | — | 输入法生态拥挤，差异化难 |

> 关键原则：**Rust core daemon 是唯一一份业务逻辑**，平台前端只做"音频采集 + 文本注入 + UI"。这是跨平台战略能成立的工程基础（详见 ARCHITECTURE.md）。

## 9. 数据与隐私

### 9.1 数据流向

```
麦克风 → 本地 daemon（内存）→ 云端 ASR Provider → daemon → 云端 Polish Provider → daemon → IME 前端 → 目标应用
                                                                                         ↓
                                                                               本地词库 / 历史（可选）
```

### 9.2 隐私承诺（写入用户协议）

1. 音频在 daemon 内存中处理，识别结束**立即丢弃**，永不持久化（即使是临时文件）
2. 文本在传给 Polish provider 时使用 HTTPS，不附带任何用户标识
3. 我们**不**用任何用户音频或文本训练模型
4. 用户可在设置中导出 / 删除本地所有词库和历史
5. 在用户标记为"敏感"的应用下（默认含网银、医疗类），强制走本地兜底

### 9.3 合规

- 中国大陆：遵守《个人信息保护法》《生成式 AI 服务管理暂行办法》
- 欧盟：GDPR；提供 DSR（数据主体请求）通道
- iOS：满足 Apple Keyboard Extension 的 Privacy Manifest 要求

## 10. 商业模式

### 10.1 定价结构

| 档位 | 价格 | 单字成本 | 适用人群 |
|---|---|---|---|
| 免费试用 | 0 元 / 1000 字 | — | 新用户 |
| 入门包 | 10 元 / 5 万字 | 0.0002 元 | 试用后第一次充值 |
| 标准包 | 50 元 / 30 万字 | 0.000167 元 | 常规付费用户 |
| 专业包 | 200 元 / 150 万字 | 0.000133 元 | 重度用户 |

> 价格在 MVP 阶段为占位值，正式上线前需根据实际 ASR + LLM 成本回填。原则：毛利率 ≥ 60%，最低档单价 ≥ 成本 × 3。

### 10.2 反订阅制理由

- 重度用户（每月 100 万字）会让订阅制亏成狗
- 轻度用户（每月 1 万字）订阅会感觉被宰
- 按量付费让两边都开心，且**与底层 API 成本结构同构**（豆包 / Qwen 都是按量计费）

### 10.3 增长路径

- M0–M1：闭门内测，工程师社区（V2EX / 即刻 / Twitter 中文圈）扩散
- M2：上线 GitHub + 知乎 + B 站技术 demo
- M3+：付费投放可选（CAC < 30 元才考虑）

## 12. 风险与对策

| # | 风险 | 影响 | 概率 | 对策 |
|---|---|---|---|---|
| R1 | 豆包流式 ASR 提价 / 限流 | 成本失控 | 中 | Provider 抽象，可一键切换 Paraformer/SenseVoice |

| R5 | 用户口音 / 方言导致识别差 | 满意度低 | 高 | 明确**非目标**；首页明示"标准普通话 + 标准英语" |
| R6 | 数据合规（被监管点名） | 业务停摆 | 低 | 隐私承诺写进用户协议；不留音频日志；接入合规 ASR |
| R7 | "AI 单人开发"叙事翻车（实际依赖多个云 API） | 品牌伤害 | 中 | 不在营销中过度强调"单人"，强调"产品哲学" |

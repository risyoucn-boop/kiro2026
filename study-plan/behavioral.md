# 行为面 STAR 故事工作表

> 不要现编故事。提前写 8–10 个，每个故事至少能挂 2 条 LP，刻意练习到能在 90 秒内讲完。

## 故事工作表（每个故事一份）

```markdown
### [故事编号] 标题（10 字内）
**主挂 LP**：
**副挂 LP**：

**S - Situation**（15 秒）
- 时间 / 项目 / 团队规模 / 你的角色：

**T - Task**（15 秒）
- 目标（量化）：
- 约束 / 难点：

**A - Action**（60–75 秒，必须是「我」做了什么）
1.
2.
3.

**R - Result**（20 秒，必须有数字）
- 短期：
- 长期 / 影响面：

**反思**（一句话）
-

**可能被追问**
- Q1:
- Q2:
- Q3:
```

## 写故事时常踩的坑

1. **主语用「我们」太多** → 改成「我做了 X，因此我们……」
2. **没有量化结果** → 哪怕是「用户反馈从 3.x 提升到 4.x」「上线后 incident -60%」也要写
3. **Action 全是技术细节** → 至少留 30% 给「为什么这么决策 / 怎么沟通」
4. **故事彼此重复** → 故意让 8 个故事来自不同维度：跨团队冲突、技术债重构、紧急上线、用户投诉、招人 / 带新人、节流降本、推不动的需求被推动了

## 推荐的 8 个「主题位」

| # | 主题 | 主挂 LP |
|---|------|---------|
| 1 | 跨团队推动一个被搁置的需求 | Bias for Action / Earn Trust |
| 2 | 一次客户驱动的设计调整 | Customer Obsession / Dive Deep |
| 3 | 反对了上级的方案并最终被采纳 | Have Backbone |
| 4 | 救火：线上 incident + 复盘 | Ownership / Dive Deep |
| 5 | 技术债 / 重构带来的长期收益 | Insist on Highest Standards |
| 6 | 限期内必须交付且砍 scope | Deliver Results / Bias for Action |
| 7 | 带新人 / mentor / 招聘环节 | Hire and Develop the Best |
| 8 | 用更少资源做更多（成本优化） | Frugality / Invent and Simplify |

## 每日 15 分钟「口头化」练习

- 抽签 1 个故事
- 录音讲一遍（不超过 2 分钟）
- 回放，砍掉填充词、重复、冗长背景
- 第二次录音，对比时长是否缩短
- 一周后重听，确认还能用同一节奏讲出来

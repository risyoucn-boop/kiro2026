# 面试当天 Checklist

## 前一天

- [ ] 提前确认面试时间、链接、面试官名单（如可知）
- [ ] 设备：摄像头、麦克风、屏幕共享各试一次
- [ ] 备用：手机热点、备用浏览器、纸笔
- [ ] 把 LP 故事矩阵打印 / 打开在第二屏
- [ ] 早睡，不再刷新题

## 当天前 30 分钟

- [ ] 喝水、上厕所
- [ ] 重读 Top 5 LP 故事的标题（不重读全文）
- [ ] 闭眼默写「系统设计 6 步法」
- [ ] 心态：把面试当成「和一个聪明同事一起讨论问题」

## 编码轮中

1. **复述题目**：用自己的话说一遍，确认 IO / 边界 / 复杂度要求
2. **给出 1–2 个 example**：自己造例子，包含一个边界
3. **先讲思路，再写代码**：暴力 → 优化，时间 / 空间复杂度同步说
4. **写代码时保持自言自语**：让面试官听到你的思路，方便给提示
5. **写完主动跑测试**：用自己造的例子在脑里 / 草稿区跑一遍
6. **主动谈 follow-up**：「如果数据规模变成 10^9，我会换成 …」

## 系统设计轮中

- 第一个 10 分钟一定花在 clarify + 估算 + API
- 不要死磕一个组件，整体跑通再回头深挖
- 主动指出 trade-off，比让面试官追问更好
- 留出最后 5 分钟谈「如果再多 1 周，我会优先做哪 2 件事」

## 行为面轮中

- 听清问题再回答，不确定就问「您是想了解 X 还是 Y？」
- 用 STAR，控制 Action ≤ 75 秒
- 把「我」「我决定」「我和 X 沟通」说清楚，不要全用「我们」
- 结尾主动给反思 / 学到的东西

## 每轮之间的 5 分钟

- [ ] 上厕所 / 喝水
- [ ] 写 1 行字：上一轮我做得最好的 1 件 + 想改进的 1 件
- [ ] 不复盘错题，不影响下一轮心态

## 结束之后

- [ ] 24 小时内写一份「面经复盘」：题目、关键问答、卡点、面试官风格
- [ ] 给自己一点正反馈，不论结果
